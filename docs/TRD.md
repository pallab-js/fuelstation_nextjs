# TRD — Technical Requirements & Stack

## 1. Stack (pinned at scaffold time)

| Concern | Choice | Version | Notes |
|---|---|---|---|
| Framework | Next.js (App Router, Turbopack) | 16.3.x | `output: 'export'` → static site |
| Language | TypeScript | 5.x | `strict: true` |
| Styling | Tailwind CSS v4 (CSS-first `@theme`) | 4.3.x | tokens authored from DESIGN.md |
| DB | Dexie (IndexedDB) | 4.4.x | `dexie-react-hooks` liveQuery |
| Client state | Zustand | 5.x | session/scope/UI only |
| Charts | Recharts | 3.x | themed to design tokens |
| Forms | react-hook-form + zod + @hookform/resolvers | latest | schema-first validation |
| Icons | lucide-react | 1.x | thin-line geometric set |
| PWA | hand-rolled SW generated by `scripts/build-sw.mjs` | — | hashed precache manifest, no plugin lock-in |
| Unit tests | Vitest | 3.x | domain logic (node env) |
| Lint | eslint-config-next + typescript-eslint | 9.x | `npm run lint` |
| License | MIT | — | `LICENSE` |

Fonts (next/font, self-hosted at build → offline-safe): **Space Grotesk** (display,
standing in for CohereText), **Inter** (body/UI, standing in for Unica77),
**JetBrains Mono** (mono labels, standing in for CohereMono).

| Command | Purpose |
|---|---|

## 3. Non-functional requirements

- **Performance:** first interactive < 3 s on mid hardware; dashboard bundle target
  < 300 KB gzipped JS (Recharts is the main weight — code-split per route via dynamic
  `import()` where it pays).
- **Data volume:** seeded ~20k sales rows; queries indexed by `[stationId+ts]`;
  selectors aggregate in O(n) with memoization; tables paginate/virtualize beyond 200 rows.
- **A11y:** WCAG 2.1 AA — visible focus (`--color-focus` ring), labelled inputs,
  keyboard-operable dialogs (focus trap + Esc), `aria-live` on toasts, ≥40 px targets.
- **Responsiveness:** ≥375 px; breakpoints per DESIGN.md (cards 3→2→1, nav collapses).
- **Browsers:** last 2 versions of Chromium/Firefox/Safari; IndexedDB required
  (guarded with a friendly blocking screen).
- **Money/units:** integer paise and millilitres everywhere; formatted via `Intl`
  (en-IN, ₹, L/ML).
- **Determinism:** seed uses a seeded PRNG (mulberry32) → identical demo data per machine.

## 4. Data integrity rules

- Writes go through repositories inside `db.transaction('rw', …)`.
- Every mutation stamps `updatedAt`; audit entries append to `auditLog`.
- zod schemas are the single source of validation (repo boundary + form resolvers share them).

## 5. Testing strategy

| Layer | Tool | Coverage target |
|---|---|---|
| Domain math (variance, aging, money, totals) | Vitest pure functions | all exported functions |
| Seed determinism (same seed → same hash) | Vitest | smoke |
| Repos (happy path) | Vitest + fake-indexeddb (optional) | core flows |
| UI | manual demo script (documented) | prototype scope |

## 6. Known risks & mitigations

| Risk | Mitigation |
|---|---|
| Static export forbids dynamic routes | detail views via `?id=` + `<Suspense>` |
| SW stale after deploy | manifest revisioned from file content hashes; skipWaiting |
| Recharts bundle weight | route-level dynamic import; lazy chart mount |
| IndexedDB unavailable (private mode) | detect + blocking screen with guidance |
| Design fonts unavailable offline | next/font self-hosts at build time |
